## Inputs and equations

An authenticated manager explicitly selects one employee already belonging to their organisation. A profile stores nullable job/education/qualification fields and distinct total professional experience, relevant occupational experience, contribution history, employer tenure and recognised base-seniority months. Unknown stays null. Negative/noninteger months and relevant experience exceeding total are refused. Ordinary daily hours are a decimal string; weekly and monthly schedules are mutually exclusive.

- Weekly ratio `r = daily_hours × days_per_week / standard_weekly_hours`.
- Monthly ratio `r = daily_hours × paid_days_per_month / rule_set.overtime_divisor(calendar_days)`. Paid days must include applicable paid rest/holidays; the interface does not claim these are attendance days.
- Require `0 < r <= 1`. Overtime must be separately supplied, never generated by a >1 ordinary schedule.
- Full-time fixed wage `F = entered_gross − housing − grocery − marriage − child`. The attraction component is retained in F. Require F not below the active rule set's monthly minimum; do not silently raise it.
- Recognised seniority months must be supplied for a work-profile calculation. Under 12 months means zero increment. For unclassified workshops at 12–23 months, use the active current-year daily increment. At >=24 months, or for a classified workshop, require the documented daily seniority amount from the manager; do not invent historical accumulated rates. An eligible declared amount cannot be below the current increment. Record its input provenance.
- Prepare exact component lines `F×r`, each of four welfare amounts `A_i×r`, and `daily_seniority×calendar_days×r`. Round each monetary line once, half up; prepared gross is the sum of these rounded lines. Publish `sum(rounded lines) − round(sum(exact lines))` as the work-profile signed residual. Attraction is a retained component of fixed wage and is scaled for tax metadata, never added twice.
- Send prepared gross/allowances and separate overtime/night hours to existing `compute_gross_to_net`, retaining the verified 1404 rule set. Pass employer tenure only to an explicit ordinary-termination scenario; no probation guess. Leave-buyout defaults remain not supplied unless given by the existing request contract.
- Premium hourly base remains the **full-time equivalent** fixed wage plus full-time seniority, so part-time status does not reduce the hourly overtime/night rate twice. The Eydi annual cap is proportioned by the same employment ratio under Art. 39; the actual-wage Eydi floor is already proportioned and must not be scaled again. Core PayrollInput carries explicit internal `premium_base_rial` and Decimal `employment_ratio` (defaults preserve existing full-time results); public generic payroll input does not allow arbitrary overrides. Provenance and hash bind those inputs. Engine version advances to 0.4.0.
- Snapshot includes original profile, full-time inputs, exact ratio, rounded prepared lines and their provenance, original engine envelope/hash, a distinct work-calculation hash, profile revision and generated_at. Snapshots are append-only and never refreshed in place.

## API and persistence

Under `/api/v1/manager/employees/{employee_id}`: GET/PUT `work-profile`; POST `work-profile/calculate`; GET `work-profile/calculations/latest`; GET/POST `work-documents`; GET `work-documents/{document_id}/content`. GET absent profile/latest yields null, not invented defaults. Tenant comes only from the session; every access first checks tenant ownership of the selected employee. Schema forbids extra client tenant/key fields.

Three new tenant tables store encrypted profile JSON, encrypted document content/metadata, and immutable encrypted result snapshots. Each table has tenant_id, an FK to the selected employee, FORCE RLS and a same-migration tenant policy. Application predicates enforce tenant equality even on local superuser connections. IDs are server generated. No changes to old manager evidence blobs or historic calculations.

## Local key and document boundary

Only `APP_ENV=local` may use the local provider. A 32-byte master is created once by an explicit setup script in workspace `.secrets/`; existing keys are never replaced. Derive a tenant-scoped DEK using HKDF-SHA256, then use existing PiiFieldTransformer with tenant/record/field/key-id AAD. Missing/invalid keys fail closed; no plaintext fallback. The database has no key material, raw filenames, profile JSON or document plaintext in new tables.

Upload size <=5,000,000 bytes, checked while reading before allocation beyond limit. Detect PDF/JPEG/PNG from server-side magic bytes, reject mismatch/other formats; do not parse/render documents or execute content. Sanitize/bound filenames and notes. Downloads are authenticated attachments with fixed detected MIME, `nosniff` and `Cache-Control: no-store`; lookup by both employee and tenant. No antivirus, OCR, signature-verification or production archive claim.

## Acceptance examples and checks

- Synthetic gross 220,000,000, zero welfare, 4 hours × 5 days/week gives ratio 5/11 and gross 100,000,000; total experience alone does not change it.
- 22 hours/week with first eligible unclassified-year seniority on 1404 (94,000/day, 30 days) adds 1,410,000 Rial; full-time gross 220,000,000 becomes 111,410,000 after 1/2 ratio and seniority.
- Monthly 4 hours × 20 paid days in a 30-day month gives ratio 4/11 and gross 80,000,000 for zero welfare/no seniority. Monthly ordinary hours above 220 are refused.
