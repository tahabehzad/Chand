| نسل | نشانه‌های فیزیکی | وضعیت |

**یافتهٔ GAP-01 (بحرانی):** محصولِ اعلام‌شده (نسل ۳) امروز **قابل استفاده نیست**، در حالی که تنها کدِ قابل اتکا متعلق به محصولی است که اسناد آن را کنار گذاشته‌اند.

**شاهد عینی:** درخواست واقعی که رابط کاربری می‌سازد (بدون `education`) با کد ۴۲۲ رد می‌شود:

```
POST /api/v1/simulations/salary-estimation
{"job_title":"توسعه‌دهنده وب","experience_years":5,"seniority_level":"mid",
 "employment_type":"full_time","city":"tehran","currency_unit":"toman"}
→ 422 {"error":{"code":"ESTIMATION_INPUT_INVALID",
        "detail":"1 validation error for EstimationInput\neducation\n  String should have at least 1 character"}}
```

و همان درخواست با افزودن `education` پاسخ می‌دهد، اما با اعدادی که در بخش ۳ بررسی می‌شوند.

## ۳. اعتبار عددی خروجی — شواهد اجراشده

### GAP-02 (بحرانی): برآورد پایین‌تر از حداقل دستمزد قانونی
- **شاهد:** برای «Senior React Developer / تهران / ۶ سال تجربه» پاسخ `primary_estimate_rial = 45,000,000` است؛ برای `mid/5سال` مقدار `30,000,000`. حداقل دستمزد ماهانهٔ ۱۴۰۴ در seed تأییدشده `103,909,680` ریال است (`backend/data/seeds/statutory_rules_1404.yaml:12`).
- **استنتاج تأییدشده:** خروجی محصول ۲۹٪ تا ۴۳٪ **کمتر از حداقل دستمزد قانونی** است.
- **تأثیر:** خروجی برای هر گفت‌وگوی استخدامی بی‌معنا و از نظر انطباقی گمراه‌کننده است.
- **فرضیه (نه واقعیت تأییدشده):** اعداد `MOCK_MARKET_DATA` احتمالاً به «تومان» نوشته شده‌اند و برچسب `_rial` گرفته‌اند (۲۵٬۰۰۰٬۰۰۰ تومان ≈ ۲۵۰٬۰۰۰٬۰۰۰ ریال که برای بازار ۱۴۰۵ معقول است). این فرضیه باید توسط مالک تأیید یا رد شود؛ در هر دو حالت دادهٔ فعلی غیرقابل استفاده است.
- **اقدام:** تا تعیین واحد و منبع داده (D-01)، نمایش هیچ عددی مجاز نیست.
- **وضعیت:** واقعیت عددی ✅ تأییدشده؛ علت (خطای واحد) ⚠️ فرضیه.

### GAP-03 (بالا): پوشش شهری وعده‌داده‌شده در برابر واقعیت
- **شاهد:** فرم ۸ شهر دارد (تهران، اصفهان، شیراز، مشهد، اهواز، تبریز، ساوه، کرج). اجرای واقعی با `seniority=mid`:

| شهر | خروجی | سطح اطمینان |
|:---|:--:|:---|
| تهران | ۳۰٬۰۰۰٬۰۰۰ ریال | high |
| ساوه | ۱۹٬۲۰۰٬۰۰۰ ریال | medium |
| اصفهان، شیراز، مشهد، اهواز، تبریز، کرج | ۰ | insufficient_data |

- **تأثیر:** ۶ از ۸ گزینهٔ رابط کاربری به «صفر ریال» می‌رسند و UI این صفر را به‌عنوان یک رقم واقعی نمایش می‌دهد (نه امتناع).
- **اقدام:** غیرفعال‌کردن گزینه‌های بدون داده، یا پیام صریح امتناع (FR-07).

### GAP-04 (بالا): تمایز نقش شغلی کار نمی‌کند
- **شاهد:** سه عنوان مختلف در تهران، با ورودی یکسان، پاسخ یکسان می‌دهند:

```
senior_react_developer     → 30,000,000
senior_backend_developer   → 30,000,000
senior_fullstack_developer → 30,000,000
```
- **علت (تأییدشده در کد):** `_find_fuzzy_match` بر اساس کلمهٔ مشترک «developer» تطبیق می‌دهد و **اولین** پروفایل را برمی‌گرداند (`matcher.py:169-180`).
- **تأثیر:** تفکیک نقش — که هستهٔ ارزش محصول است — وجود ندارد.
- **اقدام:** تطبیق قطعی بر اساس کلید نرمال‌شده + امتناع در نبود تطبیق.

### GAP-05 (متوسط): ضریب شهر عملاً هرگز اعمال نمی‌شود
- **شاهد:** `_calculate_city_factor` فهرست `["Tehran","Isfahan"]` را با حروف بزرگ مقایسه می‌کند، اما UI و API نام شهر را کوچک (`tehran`) می‌فرستند. نتیجه: ۳۰٬۰۰۰٬۰۰۰ (بدون ضریب) در برابر ۴۵٬۰۰۰٬۰۰۰ وقتی ورودی `Tehran` باشد.
- **تأثیر:** تفاوت هزینهٔ زندگی — یکی از عوامل اعلام‌شده در D-06 — در مسیر واقعی محصول حذف شده است.

## ۴. شکاف اعتماد و شفافیت (Provenance)

### GAP-06 (بحرانی): نمایش «منبع» و «وضعیت قوانین» ساختگی
- **شاهد:** `salary_estimator.py:176` → `data_sources = ["Jobinja","JobVision","Salary Survey"]` (ثابت، مستقل از دادهٔ واقعی)؛ `:192-194` → `rule_version="v1.0"`, `rule_set_status="ACTIVE"`, `engine_version="0.1.0"`؛ `service.py:85` همان `ACTIVE` را در پاسخ API می‌گذارد.
- **تأثیر:** invariant ۹ AGENTS.md (§2.9) و FR-13 نقض می‌شود: هر رقم باید provenance صادق داشته باشد. کاربر «ACTIVE» را به‌معنای «قانون تأییدشده» می‌خواند، در حالی که هیچ rule set تخمینی وجود ندارد.
- **اقدام:** حذف این فیلدها تا وجود واقعی rule set؛ یا مقدار `DRAFT`/`NONE`.

### GAP-07 (بالا): سطح اطمینان از دادهٔ ساختگی
- **شاهد:** `calculate_confidence` امتیاز را از `data_volume` و `recency_days` می‌سازد که خودشان اعداد دستیِ همان دیکشنری mock هستند (`matcher.py:228-244`). برای تهران همیشه `high` می‌شود.
- **تأثیر:** «سطح اطمینان بالا» به کاربر اطمینان کاذب می‌دهد.
- **اقدام:** تا اتصال دادهٔ واقعی، سطح اطمینان باید ثابت `insufficient_data` باشد.

### GAP-08 (بالا): مقدار مرجع قانونی اشتباه
- **شاهد:** `salary_estimator.py:284-289` مقدار `36,000,000` را با کامنت «approximate» برمی‌گرداند؛ مقدار تأییدشدهٔ ۱۴۰۴: `103,909,680` ریال (`statutory_rules_1404.yaml:12`). خطا ≈ ۶۵٪ کمتر.
- **تأثیر:** ADR-013 D-07 می‌گوید هر مقدار مرجع باید سال، تاریخ اعتبار و منبع داشته باشد؛ AGENTS.md §2.10 می‌گوید مقدار نامعلوم باید نامعلوم بماند و تخمین زده نشود.
- **اقدام:** خواندن از rule-set loader موجود (۱۴۰۴ VERIFIED) یا حذف کامل فیلد.

## ۷. حداقل مسیر تا «اولین خروجی قابل اعتماد» (پیشنهاد، نیازمند تصویب مالک)

این بخش تصمیم نمی‌گیرد؛ فقط وابستگی‌ها را مرتب می‌کند:

1. تصویب واحد پول و منبع داده (D-01) — بدون آن هر عدد بی‌معناست.
2. تصویب مدل احراز هویت (D-02).
3. حذف/آرشیو نسل‌های ۱ و ۲ از مسیر اجرا (یا تثبیت رسمی آن‌ها به‌عنوان محصول).
4. اصلاح زنجیرهٔ ورودی (education/skills) و امتناع به‌جای صفر.
5. اتصال rule-set loader برای حداقل دستمزد واقعی.
6. build سبز + تست payload واقعی UI.

> تا بند ۱ و ۲ تصویب نشوند، هر پیشرفت کد جدید احتمالاً دوباره دور ریخته می‌شود — همان الگویی که سه بار در این مخزن تکرار شده است.
