## ۴. ترتیب پیشنهادی (وابستگی‌محور، نه تاریخ‌محور)

```
G0  دروازهٔ تصمیم مالک        ← D-01 منبع داده، D-02 احراز هویت، تثبیت محصول
 │
G1  سبز کردن build و تست      ← بدون تصمیم محصول هم ممکن است (کار فنی محض)
 │
G2  صداقت خروجی               ← امتناع به‌جای صفر، حذف provenance ساختگی، حذف مرجع غلط
 │
G3  اتصال دادهٔ واقعی          ← پس از D-01
 │
G4  احراز هویت و حفاظت         ← پس از D-02
 │
G5  persistence و تاریخچه      ← migration + endpoint + UI
 │
G6  دمو و پذیرش مالک
```

### G1 — سبز کردن (بدون تصمیم محصول قابل انجام است)
| # | کار | معیار پذیرش (قابل اندازه‌گیری) |
|:--:|:---|:---|
| 1 | رفع ۹ خطای نحوی | `npx tsc --noEmit` → exit 0 |
| 2 | رفع وابستگی‌های گمشده | `tsc` بدون «Cannot find module»؛ یا حذف react-hook-form/zod |
| 3 | به‌روزرسانی تست قرارداد/ناوبری | `vitest run` → ۰ شکست |
| 4 | پاک‌سازی اسکریپت‌های موقت | `ruff check .` → exit 0 |
| 5 | رفع خطاهای type | `mypy --strict` روی ماژول‌های جدید → exit 0 |
| 6 | حذف کد مرده | `adjuster.py`/`mock_data.py` حذف یا ادغام |

### G2 — صداقت خروجی
| # | کار | معیار پذیرش |
|:--:|:---|:---|
| 1 | امتناع به‌جای صفر | برای شهر بدون داده: پاسخ فاقد هر فیلد عددی + دلیل صریح |
| 2 | حذف `rule_set_status`/`data_sources` ساختگی | پاسخ API هیچ فیلد ثابتی نداشته باشد که ادعای منبع/وضعیت کند |
| 3 | حذف یا اتصال مرجع حداقل دستمزد | مقدار برابر `103,909,680` از rule-set ۱۴۰۴ یا حذف فیلد |
| 4 | Decimal در کل مسیر | تست «هیچ float در مسیر مبلغ» سبز |
| 5 | متن فارسی پاک | تست گیت نویسه‌های خارجی سبز |
| 6 | payload واقعی UI کار کند | تست e2e با همان بدنه‌ای که فرم می‌سازد → ۲۰۰/امتناع، نه ۴۲۲ |

### G3 — دادهٔ واقعی (وابسته به D-01)
- جدول `market_salary_data` + migration + seed با `source`, `collected_at`, `expires_at`.
- حذف `MOCK_MARKET_DATA` و `MOCK_MARKET_ROWS` از مسیر اجرا.
- معیار پذیرش: هر رقم خروجی به یک ردیف داده با منبع و تاریخ قابل ردگیری باشد (FR-13).

### G4 — احراز هویت (وابسته به D-02)
- یک dependency واحد روی endpoint تخمین + rate limit روی login/تخمین.
- معیار پذیرش: درخواست بدون نشست → ۴۰۱؛ تست منفی وجود دارد.

### G5 — persistence
- migration رسمی برای `candidate_estimates` (و حذف `estimation_users` به‌نفع `users` موجود یا تأیید صریح دو سیستم).
- endpoint تاریخچه + صفحهٔ تاریخچه.
- معیار پذیرش: برآورد ذخیره و پس از restart بازخوانی شود.
